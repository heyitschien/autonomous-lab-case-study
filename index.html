01 — In 30 seconds

What this is

I direct an AI-assisted engineering process and use AI agents as builders and independent reviewers to develop a trading research system for Micro E-mini S&P 500 futures. It is deliberately built so deterministic code owns every risk and execution decision, while language models only explain, classify, and propose.

It is not a profitable bot, it does not place live trades, and no trading edge has been proven. The artifact worth showing is the laboratory around the strategy: source provenance, a deterministic market-state layer, an audit trail held to safety-critical standards, an evidence-judging discipline, and a multi-agent workflow with a human promotion gate.

This is not financial advice and not an offer of any product.

03 — The problem

Orientation under time pressure

Day trading MES demands a fast read of a moving picture: Is the market live? What did the regular session do versus the overnight session? Is this data stale? What structure is forming? Getting it wrong is expensive, and getting it from a chart alone is slow.

The first product answered that for a human. The current work asks a harder question: can a deterministic system be trusted to identify a bounded setup, evaluate risk, and eventually act in simulation — with language models contributing intelligence but never authority?

06 — Operating model

How it is built

The differentiator is not the trading idea. It is the discipline of the process that produces it.

RoleWhoAuthority
OperatorHuman (project owner)Sets intent and priorities; approves manual validation, merges, and any irreversible step. Only role that can promote work to “done”.
Builder agentAI, in-IDEImplements code, docs, tests; opens PRs; reports with exact commit SHAs. May not self-approve an important merge.
Independent review agentAI, separate contextAudits each PR against the issue’s acceptance criteria using live repo state — CI, diffs, review threads. Does not trust the builder’s summary.
Documentation agentAIMaintains institutional memory and this case study. No runtime authority.

Rules that make the review real:

  • Exact-HEAD truth. Every handoff carries the full 40-character commit SHA. If HEAD moves, the prior verdict expires and the review is redone.
  • Green is not done. Status is tracked in six distinct states — documented, implemented, automated-tests-green, CI-green, operator-verified, complete — never collapsed into one word.
  • A review comment is not proof of a defect. The reviewer confirms every concern against the code as it exists at that commit.
  • Commit-before-reveal evaluation. A hypothesis, its dataset, and its scoring are committed before out-of-sample data is revealed; holdout exposure is logged in an append-only ledger. No look-ahead, no exam re-use.
  • The judge is part of the system. Evidence-judging scripts get their own adversarial tests, because a passing check can still certify the wrong claim.
07 — Failures that improved the system

Four times it was wrong, and what changed

A clean story that hid these would be less useful. Each changed a test, a gate, or an architecture rule.

1

An external API meant something other than what the code assumed

incident SIR-DEF-001 · external-API semantic mismatch

The Sierra call for “trading day date” returns a date value (days-since-epoch style integer), not a YYYYMMDD integer. The exporter treated it as YYYYMMDD and rejected every telemetry post as an invalid trading day. Fail-closed, so nothing corrupt got through — but the operator gate was blocked.

Fix
PR #115 (merged 2026-07-23; fix commit 21e5692)
Proof
72-assertion regression suite over date-value vectors; original operator replay gate re-run and passed after rebuild
Rule added
any external value involving date, time, units, lifecycle, identifiers, or status codes must be validated against headers, docs, a fixture, and where it matters a live probe. Compilation proves availability, not meaning.
2

A validator passed on a weak proxy

incident SIR-134-001 · capture policy too loose

A capture step recorded three “market advancing” samples that all carried the same bar-start timestamp as the paused baseline — the replay clock had not moved. The validator correctly rejected it, which exposed that the capture policy itself was too permissive.

Fix
PR #142 (merged 2026-08-03; fix commit 2680236). Playing-state writes now require a strictly-later chart time; same-bar heartbeats return waiting_chart_time_advance instead of consuming a capture slot.
Lesson
“the check passed” is not the same as “the check proved the claim.” This became cross-cutting doctrine.
3

The evidence judge itself needed hardening

Phase 3 operator validation · 2026-08-08 → 2026-08-24

A sequence of independent reviews feeding PR #151 repeatedly found that a passing operator script could still certify the wrong thing: a “paused” proof that a fast replay could satisfy while still moving; a “first accepted packet” proxy weaker than the next packet; semantic-attestation files that could pass an existence check while being empty.

Consequence
an exact-claim doctrine — the judge must bind each assertion to the specific artifact (chart time, bar indices, SHA-256) it claims to prove; a paused-first machine invariant; transition-window / race analysis added to the pre-flight checklist; immutable evidence and chronology requirements.
Lesson
in a safety-critical system, the test of the tester can matter as much as the test of the product.
4

“Executed” is not “passed” — caught in review this month

issue #179 / PR #182 · in progress

While building the model-agnostic review tooling, the independent review agent blocked the PR: the new evidence gate recorded that a validation command had run, but a run that exited non-zero could still satisfy “review context complete” and allow a COMPLETE status.

Status
open, being fixed on the same issue before any dependent work starts.
Why it’s here
it shows the review process catching a subtle evidence-integrity gap in real time. That is the process working, not failing.

10 — Transferable lessons

What carries beyond trading

  • Evidence quality is the ceiling on AI usefulness. Once the deterministic inputs were clean, prompt engineering stopped being the bottleneck.
  • Separate intelligence from authority. A model becomes more useful when given less irreversible power — it can propose freely because it cannot act.
  • Green checks are not proof. Track the six truth states separately and never collapse them.
  • Test the tester. Any script that certifies a claim needs adversarial tests of its own.
  • Independent review beats self-report — including for prose. Documentation can broaden scope just like code.
  • A trustworthy notebook precedes a trustworthy strategy. The audit path was hardened to safety-critical standards before any strategy code was written.
  • Directing AI-assisted engineering is a real skill. The human job moved up: from writing every line to governing intent, architecture, evidence, and promotion.

12 — Public boundary

What this edition publishes

The source repository is private, proprietary, and co-owned. This public copy explains the engineering method without transferring or exposing the private source.

  • Sanitised. No credentials, tokens, secrets, machine-local paths, broker or account identifiers, or third-party personal data.
  • No edge leakage. No strategy parameters, trigger thresholds, or order-flow logic. High-level names only.
  • Bounded claims. Nothing implies profitability, positive expectancy, or live execution; capability states remain explicit.
  • Private evidence separated. Internal issue, PR, and commit references appear as labels only, without private links.
  • Public destination. This rendered page and its markdown source live in the public case-study repository.

Author’s note. “The operator” describes the role accurately: not every line of this system was hand-written by one person. One person set the direction and architecture, defined the evidence and safety standards, ran the independent-review model, performed the manual validations, and made every promotion decision — while AI agents did much of the implementation and a separate agent audited it. The honest version of this story is more interesting than “AI built a trading bot,” and it is the version an interviewer can trace back to commits.
